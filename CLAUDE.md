# Подсказчик для внедренца 1С - памятка для доработок

Программа для Windows: по медиа-клавише снимает активное окно, отправляет снимок в Claude через Claude Code (`claude -p`, вход по подписке) и показывает подсказку из 1-3 строк в окне поверх всех окон. Пользователь - внедренец 1С, не программист на Python: объяснять простыми словами, пособие вести в `Пособие.docx`.

## Файлы

| Файл | Что это |
| --- | --- |
| `hint.py` | Вся программа, один файл |
| `config.json` | Настройки. Значения по умолчанию и пояснения - словарь `DEFAULTS` в `hint.py` |
| `system_prompt.txt` | Инструкция для модели. Первый абзац - текст пользователя, не менять без его просьбы |
| `knowledge.txt` | Справочник внедренца: правила, проверенные и непроверенные пути 1С |
| `task.txt`, `script.txt` | Задача клиента и скрипт встречи. Данные клиента, `script.txt` в `.gitignore` |
| `run.bat`, `check.bat` | Запуск и проверка установки (`python hint.py --check`) |
| `requirements.txt`, `requirements-voice.txt` | Pillow; необязательные библиотеки голосовой клавиши |
| `tests/test_core.py` | Тесты логики, работают везде |
| `tests/smoke_ui.py` | Проверка окна и сценариев с заглушками вместо Claude и распознавания |
| `docs/make_manual.js` | Генератор `Пособие.docx` (библиотека `docx` для Node) |

## Как устроен запрос

- Команда собирается в `build_command`. Флаги проверены на Claude Code 2.1.322; перед изменением сверяться с `claude --help` и документацией, не с памятью.
- Снимок передаётся двумя способами (`image_mode` в `config.json`, функции `ask` и `ask_claude`):
  - `direct` (по умолчанию): снимок идёт прямо в сообщении как блок `image` в base64 через `--input-format stream-json`. Инструментов у модели нет (`--tools ""`), обращение к модели одно, на диск снимок не пишется. По замерам втрое дешевле и на 1-3 с быстрее, чем `file`. В прочитанной документации Claude Code формат сообщения stream-json не описан; работает на 2.1.322.
  - `file` (запасной): снимок пишется в `tmpdir/shot/shot.png`, модель читает его инструментом Read - это два обращения к модели. `--tools Read`, `--permission-mode dontAsk`: чтение вне рабочей папки запрещено режимом, внутри разрешено всё, поэтому в рабочей папке лежит только снимок.
  - Если в режиме `direct` Claude Code не вернул объект `result` (`DirectUnsupported`), программа до конца сеанса переходит на `file`. `check.bat` печатает, какой способ сработал.
- Правило о том, где лежит снимок, добавляет в системную часть код (`SHOT_RULES`), а не `system_prompt.txt`.
- `--bare` использовать нельзя: он отключает вход по подписке. `ANTHROPIC_API_KEY` убирается из окружения (`child_env`), иначе `claude -p` возьмёт ключ вместо подписки.
- Системная часть (`build_system`): инструкция, затем справочник, затем скрипт. Она не меняется между нажатиями и берётся из кэша. Всё, что меняется часто (задача, пункт скрипта, история, вопрос, расшифровка речи), идёт в тексте запроса (`build_prompt`). Не переносить изменчивое в системную часть и не менять набор инструментов между запросами: это сбрасывает кэш. Вопрос без снимка идёт той же командой, просто без блока `image`.
- История - только текст: последние `history_pairs` пар "экран - совет". Модель дописывает служебную строку `ЭКРАН: ...`, `parse_answer` её отделяет. Старые снимки не хранятся и не пересылаются.
- Снимок сравнивается с предыдущим (`signature`, `same_shot`). Одинаковый снимок без вопроса не отправляется. Любое изменение контекста (задача, скрипт, пункт, модель) сбрасывает `last_sig`.

## Windows-часть

- Клавиши: низкоуровневый перехват `WH_KEYBOARD_LL` в отдельном потоке (`KeyHook`), нажатия "съедаются" (`return 1`). Перехват переустанавливается каждые `hook_refresh_sec` секунд, чтобы быть первым в цепочке. События идут в очередь `App.events`, обрабатываются в потоке Tk (`_poll`).
- Снимок: `capture_window` берёт границы активного окна (`DwmGetWindowAttribute`), снимает через Pillow, уменьшает до `shot_width`.
- Окна программы скрыты от захвата: `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`. Каждое новое окно создаётся прозрачным, защищается и только потом показывается (`_reveal`); раз в секунду защита подтверждается (`_tick`). Стандартные диалоги Tk (messagebox) не использовать: они не скрыты.
- Главное окно не забирает фокус (`WS_EX_NOACTIVATE`), поля ввода забирают и возвращают его окну подключения (`force_foreground`).
- Временная папка приводится к полному пути (`make_workdir`): Windows выдаёт короткие имена вида `NMALAF~1`, и Claude Code тогда считает снимок лежащим вне рабочей папки. Эта ошибка уже случалась.
- Голос: `Recorder` пишет звук в память через PyAudioWPatch (WASAPI loopback - звук встречи, микрофон - по настройке), `Transcriber` распознаёт локально через faster-whisper. В Claude уходит только текст. Короткое нажатие (меньше 0,4 с) переключает в режим "нажал - нажал ещё раз", потому что часть клавиатур отпускает медиа-клавиши сама.

## Что проверено, а что нет

Среда разработки была Linux, пользователь проверяет на Windows 11, Python 3.14.

- Проверено на Windows пользователем: установка, `check.bat`, перехват клавиш, снимок окна, скрытие от захвата, запрос и ответ.
- Проверено только в Linux (виртуальный экран, `tests/smoke_ui.py`): пункты скрипта, "Вне скрипта", листание, вопрос без снимка, кнопка модели, логика голосовой клавиши.
- Не запускалось нигде на момент написания: запись звука (`Recorder`) и распознавание речи (`Transcriber.transcribe` с настоящей моделью). Ждать ошибок здесь в первую очередь; `check.bat` печатает уровень записи и ошибки.
- Непроверенные пути 1С в `knowledge.txt` помечены разделом "НЕ ПРОВЕРЕНО".

## Как проверять изменения

```
python -m unittest discover tests                 # логика, нужен Pillow (numpy - по желанию)
xvfb-run -a python tests/smoke_ui.py              # окно и сценарии, нужен Python с tkinter
python hint.py --check                            # живой запрос в Claude, тратит немного лимита
NODE_PATH=$(npm root -g) node docs/make_manual.js Пособие.docx   # пересобрать пособие
```

Правила:
- После правки `hint.py` запускать оба набора тестов. Новую кнопку или сценарий добавлять в `tests/smoke_ui.py`.
- Всё, что зависит от Windows, честно называть непроверенным, пока пользователь не запустит это у себя.
- При изменении поведения обновлять `docs/make_manual.js` и пересобирать `Пособие.docx`.
- Новые настройки добавлять в `DEFAULTS` и в `config.json`; `save_config` пишет только ключи из `DEFAULTS`.
- Лог (`hint.log`) содержит только время и длительность. Содержимое снимков, речи и ответов в лог и на диск не писать.
- Пути в интерфейсе 1С не придумывать. В `knowledge.txt` в раздел "ПРОВЕРЕНО" переносить только то, что подтверждено ИТС или пользователем в базе.
- Ветка разработки - `claude/keen-cerf-ptw6se`. В `main` лежит другой проект (ВКР), ветку в `main` не сливать.
